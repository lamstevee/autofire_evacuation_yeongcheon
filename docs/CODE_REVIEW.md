## P1 · 픽업을 대피소 도착으로 집계함

- 위치: `frontend/src/components/MapComponent.tsx:174-185`, `frontend/src/store/useSimulationStore.ts:247`.
- 차량이 배정 주민의 0.005도 이내로 접근하면 곧바로 `completeResident()`를 호출합니다. 주민은 아직 대피소에 도착하지 않았는데 진행률과 ETA는 완료로 해석합니다. 모든 주민을 마지막으로 픽업한 순간에도 차량은 대피소로 이동 중일 수 있습니다.
- 경로가 모두 끝났을 때도 주민 상태를 확인하지 않고 전원 도착 로그를 출력합니다(`MapComponent.tsx:197-203`).
- 개선: `pending → moving → completed` 상태를 실제 사용하고 차량 탑승자 목록을 관리합니다. 대피소 도착 시에만 완료 처리하며 최종 로그도 미완료 주민 수로 검증해야 합니다.

## P2 · lint가 애니메이션 콜백 자기 참조를 오류로 처리함

- 위치: `frontend/src/components/MapComponent.tsx:134-210`, 특히 207행.
- `useCallback`에 전달하는 함수가 초기화 중인 `animate` 변수를 참조합니다. 현재 ESLint의 `react-hooks/immutability` 규칙에서 오류가 발생해 lint가 실패합니다. 프로덕션 빌드 성공과 별개의 문제이며 이 검사 결과만으로 런타임 예외가 발생한다고 단정하지 않습니다.
- 개선: effect 내부의 명명된 프레임 함수나 안정적인 콜백 ref 구조로 정리하고 예약·취소 및 최신 상태 참조를 검증합니다.

## P2 · 동일 시나리오를 재생성해도 데이터가 달라짐

- 위치: `scripts/generate_mock.py:167`.
- `random.seed(hash(params.id))`의 문자열 hash는 기본 Python 실행에서 프로세스마다 달라질 수 있습니다. 시나리오 ID가 같아도 주민 좌표와 배정이 달라져 이전 결과와 비교하기 어렵습니다.
- 개선: 시나리오별 고정 정수 또는 안정적인 해시 기반 seed를 사용하고 출력 데이터에 seed를 기록합니다.

- `PHASE_LOGS`와 헤더의 API 수신·OR-Tools·Push 전송은 고정 문구이며 실제 연동 코드가 없습니다.
